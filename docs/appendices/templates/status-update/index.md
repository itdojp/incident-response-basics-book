# 状況共有テンプレ

## 更新頻度（目安）

目安であり、組織の窓口/顧客影響/法令要件がある場合はそれらを優先する。

| Severity | 更新頻度（目安） | 補足 |
| --- | --- | --- |
| P0 | 10〜15 分ごと | 影響/復旧見込みが変わらなくても「状況維持」を共有する |
| P1 | 30 分ごと | 主要な切り分け結果・次アクションを更新する |
| P2 | 60〜120 分ごと、または節目 | 影響範囲/暫定対応/復旧見込みの節目で更新する |
| P3 | 節目のみ | 予定化（いつ直す/どう検証するか）を明確にして更新する |

## 更新に含める最小項目

- 影響（誰に/何が/どの程度。確定/推定を明示）
- いま分かっている事実と未確認事項
- 次アクション（担当/期限）
- 判断が必要な事項（ロールバック、通知、外部共有など）
- 次回更新予定時刻（次にいつ共有するか）

## 記入例（最小）

```md
## いま何が起きているか
- 決済 API で 5xx が増加

## 何を試したか
- 直近デプロイ差分を確認→変更Aが疑わしい

## 次に何をするか
- ロールバック可否の確認→実施判断（検証指標: エラー率/レイテンシ）

## 影響見込み
- 決済失敗が一部顧客で継続（失敗率 6%、暫定）

## 未確認事項
- 直近変更以外の要因、セキュリティ/プライバシー疑いの有無

## 判断が必要な事項
- ロールバック可否、顧客向け通知の要否

## 次回更新予定時刻
- 11:00 JST
```
